# DeepSeek V4.1 Flash — Phase 3b-1 ("graphs first": breakable decode graphs, one readback per MoE layer, the `exl3_moe` probe) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run DSV4.1 decode under `breakable` CUDA graphs at batch size 1 (prefill eager) with EXL3 streamed experts, cut the eager streamed-MoE path to one device readback per MoE layer, probe exllamav3's fused `exl3_moe` for parity and capture over slot pointer tables, and measure all of it in one GPU window.

**Architecture:**
- **Graphs come almost for free.** `FusedMoE.forward` already runs a streamed layer's experts as an eager break under a breakable graph (`layers/moe/fused_moe_triton/layer.py:1592-1605`), because EXL3's streamer never serves graph gather. Everything else in DSV4 decode captures whole: its three `bcg_deepseek_v4_*` breaks fire for extend batches only (`models/deepseek_v4.py:2021-2026`, `:2325-2329`, `:4211-4213`). Four things stand between us and a capture:
  1. **The EXL3 server-args gate** allows only eager runs. Task 5 lets it accept decode `breakable` at batch size 1 with prefill disabled.
  2. **Engram's file-table lookup** reads its ids back to the host, and in decode it sits inside the captured segment. Task 6 turns it into an eager break.
  3. **The stream trace and route recording** would count warmup and capture forwards as real ones. Task 7 skips the trace for them; Task 8 skips route recording. Task 3 re-baselines the hot metrics after capture.
  4. **`trace_corpus.py`/`compare_oracle.py`** need a way to launch with graphs: Task 9 adds `--graphs`.
- **The per-layer syncs go on the host side of the streamer (ruling R2).** The research counts about 19 syncing readbacks per MoE layer (~780 per token). The graph break replays that eager body verbatim, so graphs alone cannot remove them. The fix reads `topk_ids` back once per layer and does everything else on the host maps:
  - **Framework part (R3; on `cc/moe-expert-plugins`, Tasks 1–3):**
    - `ExpertPinnedHostCache.gather_rows_host` classifies pinned-tier hits on the LRU's host map;
    - `ExpertStreamer.iter_gather_experts_host` classifies hot-cache hits on `ExpertHotCache.host_slot_map()` and serves them in place from the slot tensors;
    - `record_routes_host` uploads the route counts without a readback;
    - `ensure_rows` waits on a recorded CUDA event before it refills a pinned slot, so the syncs are no longer what orders slot reuse.
  - **EXL3 part (Task 8):** `Exl3MoEMethod._apply_streamed` does one `topk_ids.cpu()` and derives from it:
    - the distinct experts;
    - the routes to record;
    - every expert's `(token, slot)` pairs, uploaded once;
    - the trace's counts.

  It then calls the host-id gather.
- **`exl3_moe` probe (R6, Task 11).** A manual GPU test runs exllamav3's fused kernel against `exl3_moe_loop` on real layer rows at BS1 top-6. The layout is the one 3b-1b would use: hot-cache-shaped slot tensors, nine fixed pointer tables over slots, and a device `expert → slot` remap. It checks parity against an fp32 reference, then capture and replay after rewriting slots, remap and routes in place. The result gates 3b-1b.
- **One GPU window (Task 12):**
  - the CUDA tests and the probe;
  - the eager-versus-graph numerics check on the truncated model (R4);
  - a full-model graph smoke;
  - Window C's reduced corpus shape with graphs (R5), plus the same four sessions eager on the new code;
  - a graph-mode Nsight capture, analysed on divix01 under memory caps.

  Task 13 records the results and brings the 3b-1b go/no-go to the owner.

**Rulings this plan implements** (`.superpowers/plans-research/dsv41-phase3b/rulings.md`, owner choice "Plan 3b, graphs first"):
- **R1 (scope).** 3b-1 only. Out of scope: an in-graph RAM-hit gather, a fused `exl3_moe` in the serving path, the per-layer RAM-ensure break (3b-1b), async NVMe reads (3b-2) and copy-engine row copies (3b-3).

    if func in (torch.Tensor.__getitem__, torch.Tensor.__setitem__) and _is_bool_index(args[1]):

    if func is torch.Tensor.to and _targets_cpu(args[1:], kwargs):

class DeviceTensor(torch.Tensor):
    """A CPU tensor that stands in for device memory in CPU tests.

    Every host readback of its values, or of any tensor computed from it,
    appends the op's name to the class-level ``readbacks`` list: ``.item()``,
    ``.tolist()``, ``.cpu()``, ``bool()``/``int()``, a boolean-mask index,
    ``nonzero``, ``unique``, ``bincount``, a one-argument ``torch.where``.
    Each of these synchronizes the stream on CUDA. Values handed to the host
    stop being device tensors. Plain tensors, such as a host copy of routes,
    are never counted. Clear ``readbacks`` before the code under test.
    """

    readbacks: ClassVar[list[str]] = []

    @classmethod
    def __torch_function__(cls, func, types, args=(), kwargs=None):
        kwargs = kwargs or {}
        name, to_host = _readback(func, args, kwargs)
        if name is None:
            return super().__torch_function__(func, types, args, kwargs)
        cls.readbacks.append(name)
        if not to_host:
            return super().__torch_function__(func, types, args, kwargs)
        with torch._C.DisableTorchFunctionSubclass():
            result = func(*args, **kwargs)
            if isinstance(result, torch.Tensor):
                result = result.as_subclass(torch.Tensor)
        return result


def as_device(tensor: torch.Tensor) -> DeviceTensor:
    """``tensor``, sharing its storage, as a ``DeviceTensor``."""
    return tensor.as_subclass(DeviceTensor)

    def gather_rows_host(
        self, expert_ids: Sequence[int], outputs: dict[str, torch.Tensor]
    ) -> PinnedGatherResult:
        """``gather_rows`` for expert ids already on the host, with no device readback.

        Hits and misses come from the LRU's host map rather than a device
        lookup. Chunks follow ``gather_rows``'s ``evictable_rows()`` rule, and
        each chunk's slots go up in one non-blocking upload. Only an admission
        blocks the host: ``ensure_rows`` waits for the copies queued out of the
        slabs before it refills a slot. The LRU order, slots, counters and rows
        are those ``gather_rows`` produces for the same ids.
        """
        if self.capacity == 0:
            raise ValueError("pinned host cache has no rows")
        expert_ids = [index(expert_id) for expert_id in expert_ids]
        hit_rows = 0
        miss_rows = 0
        populated_before = self.stats.populated_bytes
        fallback_used = False
        total = len(expert_ids)
        start = 0
        while start < total:
            evictable = self.evictable_rows()
            chunk_rows = total - start
            if (
                evictable >= 1
                and chunk_rows > evictable
                and len(set(expert_ids[start:])) > evictable

                chunk_rows = evictable
            chunk = expert_ids[start : start + chunk_rows]
            hits = [expert_id for expert_id in chunk if expert_id in self._lru]

def _host_index_tensor(values: Sequence[int], device: torch.device) -> torch.Tensor:
    """``values`` as an int64 tensor on ``device``, with no host sync.
