# F125 · RAM prefetch: promote landed rows into the tier map before the target layer

Status: ready · Brief v3 · written by hx from hx.db; edit the plan in hx, not here.

**Goal:** A speculative row that has landed in the prefetch pool before its target layer's record is published becomes an ordinary RAM-tier entry in that layer's map, so the GPU types it as a RAM hit (eligible for the CPU/link split) instead of a miss. Opt-in behind a flag, default off; the device code is unchanged.

## Questions

- **Q1** §1.2 says the claimer takes 'row r's tier lock', but the tier has no lock. Each NUMA group's service thread owns its own slots of every row with no mutex, so a claimer on group 0 that promotes group 1's pool rows would race group 1's thread, which may still be in `commit_inserted_locked` for row r's record N, or serving row r's backstop. How should cross-group promotion be made safe? _(v3)_
- **Q2** The served A/B (§2 Testing) follows `RAM_PREFETCH_FIXED_SPLIT_NEXT_HANDOFF.md` and the 2026-10-13 `read_split.py` measure, but neither file is in this checkout. Where should the capture task get them? _(v3)_
